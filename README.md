# Multi-tenant AI Assistant Backend

Production-minded Fastify/TypeScript backend for isolated RAG assistants, website chat, lead capture, and notifications. It runs completely offline by default.

## Quick start

```bash
cp .env.example .env
# Set a long random ADMIN_API_KEY. Do not commit it.
npm install
npm run build
npm start
```

Node 24+ is required (`node:sqlite`). Development: `npm run dev`. API docs are represented below; no tenant is seeded.

## API

- `GET /health`, `/ready`, `/metrics`
- `POST/GET /admin/clients`, `GET/PATCH/DELETE /admin/clients/:id`
- `POST /admin/clients/:id/rotate-key`
- `POST /admin/clients/:id/prompt` (TXT/MD), `/config` (strict JSON)
- `POST /admin/clients/:id/knowledge` (multipart field `file`, TXT/MD/PDF/DOCX, 10 MiB)
- `POST /admin/clients/:id/knowledge/rebuild`, `GET /admin/clients/:id/leads`
- `POST /v1/chat`, `POST /v1/leads`
- `/widget.js`, `/demo.html`

Admin calls require `X-Admin-API-Key`. Public calls require `X-API-Key` and an `Origin` whose normalized host and optional port exactly match an allowlisted domain. API keys are shown only on creation/rotation and only SHA-256 digests are persisted.

Client config strictly supports company/assistant names, team email, model, temperature, language, lead settings, notification channels, theme, widget settings, fallback text, retrieval tuning, and analytics settings. Allowed domains remain a separately indexed authorization field.

Create a tenant:

```bash
curl -X POST http://localhost:3000/admin/clients \
 -H "X-Admin-API-Key: $ADMIN_API_KEY" -H 'content-type: application/json' \
 -d '{"name":"Acme","slug":"acme","domains":["www.acme.test"],"prompt":"Be concise.","config":{"assistantName":"Acme Assistant","fallbackMessage":"I cannot answer that from Acme knowledge."}}'
```

Upload knowledge with `curl -F file=@handbook.pdf .../knowledge`. Embed the returned `embedCode` on the allowlisted site. Session IDs are generated by the API and retained by the widget.

## Configuration and providers

`EMBEDDING_PROVIDER=local|openai`, `LLM_PROVIDER_TYPE=local|openai-compatible`, `VECTOR_PROVIDER=local|qdrant`, and `NOTIFICATION_PROVIDER=outbox|smtp`. Generic chat and Qdrant/SMTP settings are in `.env.example`; OpenAI-compatible embeddings retain their `OPENAI_*` settings. `/health` states active providers and safe diagnostics; `/ready` fails when one is not configured/reachable.

Local vector persistence is suitable for single-process development. Qdrant uses one collection with a mandatory `clientId` payload filter. In production, run Qdrant with authentication/TLS and network isolation. Replace `LocalStorage` behind `ObjectStorage` with an S3-compatible adapter using a private bucket, server-side encryption, tenant prefixes, IAM least privilege, and signed administration access.

SQLite is behind `Repository`. For PostgreSQL, implement the same interface using a pooled driver/ORM, translate schema types and transactions, add migrations, tenant-index all high-volume tables, and use row-level security as defense in depth. Run dual-write/backfill verification or maintenance-window export/import before switching providers. Avoid SQLite on multiple app replicas.

## Security and operations

Helmet, size limits, strict Zod schemas, uniform safe errors, exact origins, per-IP rate limits, path validation, hashed keys, foreign keys, audit records, and log-header redaction are enabled. Put TLS and an additional edge limiter/WAF in front; rotate admin/tenant credentials; restrict `/metrics` at the network layer; use a secrets manager. Public CORS reflection does not grant access: authenticated routes independently require exact origin validation.

Backup all local state while the app is stopped (or after a SQLite checkpoint):

```bash
npm run backup -- /secure/backups
npm run restore -- /secure/backups/backup-TIMESTAMP
```

Backups include SQLite metadata/audit/usage logs, objects, vectors, and outbox with SHA-256 checksums. Encrypt and replicate them externally. Qdrant/S3/PostgreSQL deployments must use each provider's snapshot/versioned backup facilities; these local scripts do not snapshot remote providers.

## Generic chat provider configuration

Chat configuration now uses only generic `LLM_*` names. `src/config/llm.ts` is the single configuration source and `createLlmProvider()` is the construction boundary. Keep `LLM_PROVIDER_TYPE=local` for offline use. For NVIDIA, OpenAI, OpenRouter, Groq, Together, DeepSeek, or another OpenAI-compatible endpoint, set:

```dotenv
LLM_PROVIDER_TYPE=openai-compatible
LLM_PROVIDER_NAME=nvidia
LLM_BASE_URL=https://integrate.api.nvidia.com/v1
LLM_MODEL=moonshotai/kimi-k2.6
LLM_API_KEY_ENV=LLM_API_KEY
LLM_API_KEY=<injected secret>
```

This is an example shape, not a claim that the listed account/model is available. Standard compatible providers retain `/chat/completions`, `/models`, Bearer authorization, and no query by default. Azure OpenAI and other non-default layouts are configured with `LLM_CHAT_PATH`, `LLM_HEALTH_PATH`, `LLM_QUERY_PARAMS`, `LLM_AUTH_HEADER_NAME`, and `LLM_AUTH_SCHEME`; see the provider guide for an `api-key` Azure example. Keys remain exclusively in the environment variable named by `LLM_API_KEY_ENV`, never generic headers or query parameters. See [Provider Configuration Guide](docs/PROVIDER_CONFIGURATION_GUIDE.md), [Deployment Guide](docs/DEPLOYMENT_GUIDE.md), [Migration Notes](docs/MIGRATION_NOTES.md), [Test Report](docs/TEST_REPORT.md), and [Production Readiness Report](docs/PRODUCTION_READINESS_REPORT.md).

`.env` is loaded by both development and built server entry points. Platform-injected variables take precedence. Non-local startup fails if its URL, model, or referenced secret is missing. Calls have per-attempt abort timeouts and retry only network failures plus 408/409/425/429/5xx responses. `/health` preserves `provider` and `connected` while adding safe configured/reachable/authentication/status/model/base URL diagnostics; `/ready` returns 503 when a required provider probe fails.

Knowledge uploads are not count-limited across requests. Uploading a new filename appends its vectors, re-uploading a filename replaces only that source, and rebuild atomically at the service level clears/reconstructs the tenant index. Tenant filtering remains mandatory.
